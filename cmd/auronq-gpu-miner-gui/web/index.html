Kopanie AuronQ

Automatyczny wybór CUDA lub bezpiecznego CPU, monitoring sprzętu i kopanie solo lub w basenie.

Konfiguracja

Solo: nagroda za blok. Pool: adres wypłat używany jako login workera.
AUTO używa CUDA, gdy jest dostępna i poprawna; w przeciwnym razie bezpiecznie przechodzi na CPU.
0 = profil bezpieczny: około jednej czwartej logicznych CPU, maks. 2 wątki. Każdy wątek AQM64 używa ok. 64 MiB.
—
Tryb AUTO celuje ok. 5°C niżej, płynnie reguluje obciążenie i przy limicie wykonuje automatyczne schłodzenie. Dodatkowy fail-safe zatrzymuje miner tylko przy dalszym wzroście temperatury.
Czas pomiaru każdego rozmiaru batch.
Wbudowana obsługa MeshMiner 0.8.35+: AQM64/AURQ, CPU, NVIDIA CUDA, wiele GPU, autotune kart i automatyczny wentylator. Aplikacja nie pobiera zewnętrznego EXE bez Twojej decyzji.
MeshMiner 0.8.35 deklaruje opłatę deweloperską 0,5% na MeshPool i 1,2% na innych poolach.
Możesz wpisać dowolny kompatybilny z AuronQ endpoint host:port albo stratum+tcp://host:port. Dla RPlant skopiuj aktualny endpoint z zakładki Connect.
0 = AuronQ ustawia konserwatywny profil CPU; maksymalnie 16 wątków po 64 MiB.
Puste = automatycznie szukaj meshpool-miner.exe / meshminer.exe obok AuronQ lub w folderze MeshMiner obok niego.

Jak tworzone są peery

Node startuje z bootstrap peerami, uczy się kolejnych przez P2P i zapisuje publiczny peer store.
Z włączonym publicznym nodem aplikacja utrzymuje mapowanie UPnP TCP/18444 przez cały czas działania full noda i wysyła ogłoszenia do peerów, które wykonują callback-verification.
Jeśli operator ma CGNAT lub router bez UPnP, node pozostaje outbound-only. Nadal waliduje, kopie, synchronizuje i przekazuje bloki przez połączenia wychodzące.
